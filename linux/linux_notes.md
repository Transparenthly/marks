# Конспект: основы Linux (день 1)

## 1. Текстовый редактор в терминале

`nano file.txt` — открывает/создаёт файл. Если файла нет — создастся при сохранении.

Управление:
- `Ctrl+O` — сохранить (Write Out), затем Enter для подтверждения имени
- `Ctrl+X` — выйти

**Нюанс:** большинство утилит Linux не требуют, чтобы файл уже существовал — создают сами.

`vim` — альтернатива, мощнее, но модальный (нужно переключаться между режимами команд и ввода текста), выше порог входа. Осваивать отдельно, не параллельно с другими темами.

## 2. Потоки ввода-вывода и редирект

Три стандартных канала (file descriptors):
- **stdin** (0) — вход, по умолчанию клавиатура
- **stdout** (1) — обычный вывод, по умолчанию экран
- **stderr** (2) — вывод ошибок, **отдельный** от stdout канал, тоже по умолчанию экран

Зачем разделены stdout/stderr: чтобы можно было перенаправлять по отдельности (например, сохранить результат, но ошибки оставить видимыми в терминале).

### Операторы редиректа

| Оператор | Действие |
|---|---|
| `>` | stdout → файл, **перезаписывает** содержимое |
| `>>` | stdout → файл, **дописывает** в конец |
| `2>` | stderr → файл |
| `2>&1` | направить stderr туда же, куда сейчас направлен stdout |

**Важный нюанс с `2>&1`:** порядок имеет значение.
```bash
command > out.log 2>&1
```
Сначала stdout уходит в `out.log`, потом stderr "присоединяется" к тому же назначению. Если переставить местами — не сработает как надо.

**Нюанс:** даже команда, завершившаяся с ошибкой, всё равно создаёт файл, указанный после `2>` — сам факт перенаправления не зависит от результата команды.

### Пайпы (`|`)

Соединяет stdout одной команды со stdin другой:
```bash
ls | wc -l
```
Философия Unix: маленькие утилиты, каждая делает одну вещь, пайпы позволяют строить конвейеры.

### Heredoc — многострочный ввод без редактора

```bash
cat > file.txt << EOF
строка 1
строка 2
EOF
```
Всё между `<< EOF` и `EOF` идёт в stdin команды `cat`, `>` перенаправляет вывод в файл.

**Нюанс с echo:** поведение `echo -e "text\n"` (интерпретация `\n` как переноса строки) зависит от того, какой именно `echo` выполняется (bash builtin vs dash). Надёжнее для многострочного текста — `printf` или heredoc, а не `echo -e`.

## 3. Переменные окружения

`env` — показать все текущие переменные сессии.

`echo $PATH` — список директорий через `:`, по которым bash ищет исполняемые файлы при вводе команды. Если команда не найдена ни в одной папке из PATH — `command not found`.

`type ls` или `command -v ls` — узнать, что реально выполняется при вводе команды (может быть alias, функция или путь к бинарнику). Утилита `which` в Arch по умолчанию не установлена — эти два варианта её заменяют.

### Обычная переменная vs export

```bash
MY_VAR="hello"        # видна только в текущем shell
export MY_VAR="hello" # видна и текущему shell, и всем дочерним процессам
```

**Проверка на практике:** если создать переменную без export и потом зайти во вложенный `bash`, `echo $MY_VAR` там будет пустым. С `export` — значение видно и во вложенном shell. Дочерние процессы наследуют только exported-переменные.

### .bashrc vs .bash_profile / .profile

- **.bashrc** — выполняется при каждом открытии нового интерактивного терминала. Сюда кладут алиасы, PATH-добавления, PS1.
- **.bash_profile / .profile** — выполняется при логин-сессии (SSH-вход, TTY-логин).

Типичное содержимое `.bashrc` в Arch:
```bash
[[ $- != *i* ]] && return   # если shell не интерактивный — выйти сразу
alias ls='ls --color=auto'
alias grep='grep --color=auto'
PS1='[\u@\h \W]\$ '
```
`PS1` — переменная, задающая вид приглашения терминала (`\u` — юзер, `\h` — hostname, `\W` — текущая папка, `\$` — символ `$`/`#`).

## 4. Работа с текстом

### grep — поиск строк по паттерну
```bash
grep "cat" file.txt
grep -i "CAT" file.txt   # -i: игнорировать регистр
grep -c "dog" file.txt   # -c: посчитать количество совпадений
grep -v "cat" file.txt   # -v: инвертировать — строки БЕЗ паттерна
grep -n "bird" file.txt  # -n: показать номера строк
```

### cut — вырезать колонку по разделителю
```bash
cut -d: -f2 file.txt   # -d — разделитель, -f — номер поля
```

### sort — сортировка строк
```bash
sort file.txt      # по алфавиту
sort -r file.txt    # обратный порядок
```

### uniq — убрать повторяющиеся строки
**Ключевой нюанс:** убирает повторы только если они идут **подряд**. Поэтому почти всегда используется в связке с sort:
```bash
sort file.txt | uniq
sort file.txt | uniq -c   # -c: посчитать, сколько раз встречается каждая строка
```

### wc — подсчёт
```bash
wc -l file.txt   # строки
wc -w file.txt   # слова
wc -c file.txt   # байты
```

### awk — обработка по колонкам
Каждая строка — набор полей ($1, $2... $0 — вся строка), по умолчанию разделитель — пробел.
```bash
awk '{print $1}' file.txt
awk '$1 == "cat" {print $2}' file.txt   # с условием
```

### sed — потоковый редактор, замена текста
```bash
sed 's/cat/CAT/' file.txt      # заменяет только первое совпадение в строке
sed 's/cat/CAT/g' file.txt     # g — заменить ВСЕ вхождения в строке
sed -i 's/cat/CAT/g' file.txt  # -i (in-place) — реально изменить файл, а не просто вывести
```
**Нюанс:** без `-i` sed ничего не меняет в файле, только выводит результат в stdout.

### xargs — превратить stdin в аргументы командной строки
**Проблема, которую решает:** многие команды (`rm` и др.) ожидают аргументы командной строки, а не stdin. Пайп передаёт именно stdin.
```bash
find . -name "*.txt" | xargs rm
```
`find` выводит список путей в stdout → `xargs` превращает их в аргументы для `rm`.

## 5. Bash-скриптинг

### Шебанг
```bash
#!/bin/bash
```
Первая строка файла, начинающаяся с `#!` — говорит ядру, каким интерпретатором исполнять скрипт при прямом запуске (`./script.sh`). Без шебанга система не знает, чем обрабатывать файл при прямом вызове.

### Подстановка команды
```bash
echo "Сегодня: $(date)"
```
`$(команда)` выполняет команду и подставляет её вывод в текст.

### Запуск скрипта — два способа

| Способ | Нужен ли chmod +x |
|---|---|
| `bash script.sh` | нет, интерпретатор указан явно |
| `./script.sh` | да, обязателен |

```bash
chmod +x script.sh
./script.sh
```
**Нюанс:** `./` перед именем обязателен — bash не ищет исполняемые файлы в текущей директории по умолчанию (в отличие от папок из PATH), это защита от случайного запуска файла вместо системной команды с тем же именем.

### Аргументы скрипта
```bash
$0   # имя самого скрипта
$1, $2...  # позиционные аргументы
$#   # количество аргументов
```

### Условия
```bash
if [ $NUM -gt 5 ]; then
    echo "Больше пяти"
else
    echo "Не больше пяти"
fi
```
**Нюансы синтаксиса:**
- Пробелы вокруг `[` и `]` обязательны — `[$NUM -gt 5]` без пробелов даст ошибку синтаксиса
- Для чисел: `-gt`, `-lt`, `-eq`, `-ne`, `-ge`, `-le` (не `>`, `<`, `==` внутри одинарных скобок)
- Для строк: `[ "$STR" = "текст" ]` — одинарный `=`
- `fi` закрывает `if` (перевёрнутое имя — общий паттерн для всех блочных конструкций bash, `done` закрывает циклы)

### Циклы
```bash
for animal in cat dog bird; do
    echo "$animal"
done

for file in *.txt; do    # glob-паттерн, bash разворачивает в список файлов до выполнения
    echo "$file"
done

COUNT=1
while [ $COUNT -le 5 ]; do
    echo "$COUNT"
    COUNT=$((COUNT + 1))   # арифметическое расширение, обычный + внутри кавычек — просто текст
done
```

### Функции
```bash
greet() {
    echo "Привет, $1!"
}
greet "Мир"
```
Внутри функции `$1` — аргумент, переданный именно функции, а не всему скрипту.

### Exit-коды
```bash
ls /tmp
echo $?
```
`$?` — exit-код последней выполненной команды. `0` = успех, любое другое число = ошибка.

Практическое применение:
```bash
mkdir testdir
if [ $? -eq 0 ]; then
    echo "Папка создана успешно"
else
    echo "Ошибка создания папки"
fi
```

## 6. SSH

### Принцип асимметричного шифрования
- **Приватный ключ** — остаётся только у тебя, никогда не передаётся
- **Публичный ключ** — раздаётся свободно, кладётся на сервер

Сервер проверяет доступ к приватному ключу, не видя его самого. Компрометация публичного ключа ничего не даёт злоумышленнику — в отличие от пароля, который можно перебрать.

### Генерация ключей
```bash
ssh-keygen -t ed25519 -C "комментарий"
```
- `-t ed25519` — современный алгоритм (быстрее и надёжнее старого RSA)
- `-C` — просто метка, не влияет на безопасность
- Путь по умолчанию: `~/.ssh/id_ed25519` (приватный) и `~/.ssh/id_ed25519.pub` (публичный)
- Passphrase — доп. пароль на сам ключ-файл, можно оставить пустым для учебных целей

**Нюанс прав доступа:** приватный ключ должен иметь права `600` (только владелец читает/пишет) — SSH откажется работать, если права слишком открытые.

### Передача публичного ключа на сервер
```bash
ssh-copy-id user@server_ip
```
Подключается по паролю один раз, дописывает публичный ключ в `~/.ssh/authorized_keys` на сервере.

Ручной эквивалент:
```bash
cat ~/.ssh/id_ed25519.pub | ssh user@server_ip "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```

### Подключение
```bash
ssh user@server_ip
```

### Конфиг для алиасов серверов — `~/.ssh/config`
```
Host myserver
    HostName 123.45.67.89
    User myuser
    Port 22
    IdentityFile ~/.ssh/id_ed25519
```
После этого: `ssh myserver` вместо полной команды.

### Проброс портов
```bash
ssh -L 8080:localhost:80 user@server_ip
```
Трафик на `localhost:8080` твоей машины туннелируется через SSH и приходит на `localhost:80` сервера.

### Копирование файлов через SSH
```bash
scp file.txt user@server_ip:/home/user/          # локальный → сервер
scp user@server_ip:/home/user/file.txt ./         # сервер → локальный

rsync -avz file.txt user@server_ip:/home/user/    # умнее: копирует только изменения
```
`-a` (archive, сохранить права/даты), `-v` (verbose), `-z` (сжатие).
